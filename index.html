Chapter 4

Register Transfer & Micro-Operations

A processor is, at bottom, a set of registers and a handful of circuits that move bits between them. Chapter 4 builds the vocabulary for that movement — the notation, the shared wiring, and the arithmetic/logic/shift hardware — so that Chapter 5 can describe a whole computer as nothing more than a long, precisely timed list of these movements.

4.0Micro-operations & Timing

A micro-operation is the smallest operation a processor performs in a single clock period: copying a register, adding two registers, shifting one bit left. An instruction like ADD is not itself a micro-operation — it is a short sequence of them, spread across several clock periods. Everything in this chapter, and everything the control unit does in Chapter 5, is built by combining micro-operations.

Register transfer notation

We write a transfer with an arrow, source on the right:

NotationR2 ← R1 means: copy the contents of R1 into R2. R1 is left unchanged; whatever R2 held is overwritten. Nothing happens to any other register.

Most transfers only happen when some condition holds — a control signal must be 1. That condition is written before a colon, as a statement, not as part of the transfer itself:

Conditional transferT3: R2 ← R1 means: if timing signal T3 is currently 1, then copy R1 into R2 on this clock edge. If T3 is 0, R2 keeps its old value.

A comma separates micro-operations that happen at the same clock edge, from the same condition:

Simultaneous transferT3: R2 ← R1,  R1 ← R2 swaps R1 and R2 in one clock period — this is only correct because of how clocking works, explained next.

Why the swap works: edge-triggered clocking

Every register here is built from D flip-flops. A flip-flop has a data input, a Load (or "enable") control input, and a clock input. Its output only changes at the rising edge of the clock, and only if Load was 1 during the clock period leading up to that edge. Two consequences follow directly from this, and both matter constantly from here on:

  • Nothing changes mid-cycle. Every register reads its inputs continuously, but the output only updates at the edge — so during one whole clock period, a register's output is a stable, known value that the rest of the circuit can safely use.
  • Simultaneous transfers see the old values. In R2 ← R1, R1 ← R2, both flip-flop banks latch their new data at the same edge, from the values R1 and R2 held before that edge. Neither register's update can "leak" into the other's input first — the swap is correct by construction, not by luck.

The figure below shows exactly this: Load(R2) is held at 1 for one full clock period, but R2's output does not change until the following rising edge — that's the instant, and the only instant, the new value takes effect.

4.1The Wiring Problem

Suppose we have eight registers and want any one of them to be able to transfer into any other. Wiring a dedicated path between every pair takes n(n−1) directed connections — 56 separate wires for 8 registers, each needing its own driver and its own destination-select logic. That does not scale, and most of those paths are used only rarely. The fix used in every real processor is to give every register access to one shared communication path — a bus — and add control logic that lets exactly one register write to it at a time.

4.2The Common Bus

A bus is just a set of wires (16 of them, one per bit, for a 16-bit machine) that every register can potentially drive. The entire discipline of bus design comes down to one rule:

The one ruleAt any instant, at most one source may actively drive the bus. Every other register must present a high-impedance (disconnected) output, or its data would collide electrically with the active source.

There are two standard ways to enforce that rule in hardware.

Three-state buffers (used in the Basic Computer)

Each register's output passes through a three-state buffer before reaching the bus. Unlike an ordinary gate, a three-state buffer has three possible outputs: logic 0, logic 1, and high-impedance (Hi-Z) — electrically equivalent to being unplugged. A separate enable line per buffer decides which state applies: enable = 1 passes the data through, enable = 0 forces Hi-Z. A small decoder converts a binary select code into exactly one active enable line, guaranteeing the one rule above is satisfied by construction — the decoder physically cannot assert two outputs at once.

Multiplexers (an equally valid alternative)

Instead of letting every register push onto a shared wire, a multiplexer-based bus makes the bus itself a bank of MUX gates — one per bit — each with an input from every register and a shared select code that chooses which register's bit reaches the output. There is no Hi-Z state anywhere; the MUX always outputs exactly one of its inputs. Electrically simpler to reason about, at the cost of needing a full k-input multiplexer per bit rather than one small buffer per register.

Three-state buffer busMultiplexer bus
Idle stateHi-Z (disconnected)still drives a value

Both implement the same abstraction — one shared 16-bit path, one active source at a time — so the RTL notation and the timing rules from this point on don't care which one sits underneath.

4.3Memory Transfer

Memory is treated as just another device on the bus, with one difference: you can't address "memory" directly the way you address a register — you first have to say which word of memory you mean. That's the job of the Address Register (AR). The notation M[AR] means "the memory word currently addressed by AR," and it behaves exactly like a register name inside RTL statements:

NotationDR ← M[AR]  reads the word AR is pointing at into DR (a memory read).
M[AR] ← DR  writes DR's contents into the word AR is pointing at (a memory write).

Mechanically, memory has its own read/write control lines and its own timing: put an address on AR, assert Read or Write for one clock period, and the transfer completes. Memory is not conceptually different from a register on the bus — it's a very large one, selected by address instead of by name.

Looking aheadChapter 5's entire fetch cycle is built from two of these: AR ← PC then IR ← M[AR]. Every memory-reference instruction — AND, ADD, LDA, STA… — ends the same way: one more M[AR] read or write.

4.4Arithmetic Micro-Operations

Four operations cover essentially every arithmetic micro-operation a basic processor needs, all performed between the accumulator and one operand register, with a carry Cin / Cout at the chip boundary:

SymbolicMicro-operationMeaning
R ← R + 1Incrementadd one to a register
R ← R − 1Decrementsubtract one from a register
R3 ← R1 + R2Addbinary addition, carry propagates
R3 ← R1 + R2′ + 1Subtractadd the two's complement of R2

Subtraction being written as "add the complement, plus one" isn't a notational trick — it's literally how the hardware does it, and it's why one circuit can implement both add and subtract with a single extra control input.

Where you'll see this againIncrement is not a special circuit of its own — it's the same adder with the second input forced to all-1s (which equals −1) or, more simply, hardwired as +1 with B=0, Cin=1. In Chapter 5, PC ← PC + 1 after every fetch is exactly this increment path, and AR ← AR + 1 plays the same role during indirect addressing.

4.5Logic Micro-Operations

4.6Shift Micro-Operations

A shift moves every bit of a register one position left or right. In hardware this is not computed — it's wired: each flip-flop's data input is simply connected to its neighbor's output rather than to combinational logic, so a "shift" is just a transfer that happens to be diagonal instead of straight across.

  • Logical shift — 0 is shifted into the end that opens up; the bit that falls off the other end is simply lost (or captured in a carry flip-flop).
  • Circular shift (rotate) — the bit that falls off one end is fed back into the other end, so no information is lost.
  • Arithmetic shift — shifting left is multiplication by 2 (0 fills in); shifting right divides by 2 while copying the sign bit into the vacated position, so a negative two's-complement number stays negative.
Overflow in an arithmetic shift-leftMultiplying by 2 can overflow an n-bit signed register even when neither operand looked large. For an 8-bit AC, the check is V = C7 ⊕ C8 — the two bits nearest the sign position. Example: A = 0100 0001 (+65) shifted left gives 1000 0010, which reads as negative. Bits 7 and 8 differ, so V=1 flags the result as invalid.

4.7The ALU

The Arithmetic Logic Unit is not a fourth kind of circuit — it's the arithmetic unit, the logic unit, and the shift unit built in Figures 4-4 and 4-5, wired in parallel off the same two operand inputs, with one output selector choosing which of the three results actually reaches the bus. Only the selected section's result matters; the other two compute values that are simply discarded that cycle.

Chapter 4 — key takeaways

  • Micro-operations are elementary, clock-scoped operations; RTL notation (R2 ← R1, conditions before a colon, commas for simultaneity) describes them precisely.
  • Transfers are edge-triggered — a held Load signal only takes effect at the next clock edge, which is exactly what makes simultaneous swaps correct.
  • A common bus avoids n(n−1) dedicated wires; three-state buffers (or MUXes) plus a decoder guarantee exactly one active source.
  • M[AR] treats memory as one more device on the bus, addressed rather than named — this notation carries directly into Chapter 5.
  • Arithmetic (add/sub/inc/dec), logic (AND/OR/XOR/NOT, and their bit-manipulation uses), and shift are three parallel hardware units, combined by one selector into the ALU.
End of Chapter 4

Chapter 5

Basic Computer Organization

Chapter 4 gave us registers, a shared bus, and an ALU. Chapter 5 wires them into an actual computer and adds the one ingredient that was missing: a control unit that reads instructions out of memory and, cycle after cycle, asserts exactly the right conditions to turn each one into the correct sequence of Chapter-4 micro-operations.

5.0System Organization

The Basic Computer has eight registers, a 4096-word memory, one common bus, an ALU, and a control unit — nothing else. Every one of the ideas below is a consequence of just these pieces existing and being wired the way Chapter 4 described.

5.1Registers & Instruction Format

Eight registers, each with a specific job:

Why bit 15 is overloadedBit 15 means "indirect addressing" for a memory-reference instruction — but for register- and I/O-reference instructions there is no address field to be indirect about, so the control unit repurposes that same bit as the I/O/register-reference distinguisher. §5.4 shows exactly how it tells the two apart.

5.2Generating Timing Signals

Everything so far has talked about signals named T0, T1, T2… as if they simply exist. They don't — they're generated by two small pieces of hardware working together, and understanding them removes the last piece of "magic" from RTL statements like T0: AR ← PC.

  • The Sequence Counter (SC) is a 3-bit counter, clocked every cycle, that simply counts 0, 1, 2, 3… — it has no idea what instruction is running.
  • A 3-to-8 decoder takes SC's binary value and turns it into eight separate lines, exactly one of which is 1 at a time: line Tk is 1 precisely when SC = k.

So T3 isn't a special signal — it's just "the decoder output for SC = 3." The control unit's job is then to combine these T-lines with bits of IR (via more decoding, §5.4) to produce the actual Load/Increment/Clear signals that reach registers.

5.3The Fetch Cycle

Every single instruction, no matter what it turns out to be, begins with the identical two-step fetch — this is the "always" part of the instruction cycle, and it never depends on IR because IR doesn't hold anything meaningful yet.

T-stateMicro-operationWhat's happening
T0AR ← PCpoint AR at the next instruction
T1IR ← M[AR],  PC ← PC + 1read the instruction in, and simultaneously advance PC — both use the bus in the same clock period because IR's read and PC's increment don't need the same bus cycle
T2(decode — see §5.4)SC's third state is spent classifying, not moving data
A subtlety worth pausing onAt T1, IR ← M[AR] needs the bus to carry data from memory, while PC ← PC + 1 needs the bus to carry PC's incremented value into PC. These don't collide because the increment circuit reads PC's own current value directly, not off the shared bus — only one of the two transfers actually needs the bus that cycle.

5.4Decoding the Instruction

At T3, the control unit has 16 bits sitting in IR and needs to answer one question: memory-reference, register-reference, or I/O? This is done with a second decoder — separate from the timing decoder in §5.2 — that reads IR's bits 14–12 directly.

  • The opcode decoder is a 3×8 decoder fed by IR(14–12), producing eight lines D0…D7 — one per possible opcode pattern.
  • D0…D6 correspond to the seven memory-reference opcodes (AND, ADD, LDA, STA, BUN, BSA, ISZ).
  • D7 means bits 14–12 were all 1 — not a memory-reference instruction. It's either register-reference or I/O.

To break that last tie, the control unit looks at IR bit 15, relabelled I at this point:

D7 = 1  (bits 14–12 were 111)
I = 0
Register-referencebits 11–0 select one of 12 fixed operations (CLA, CLE, CMA…), decoded directly, no address field
I = 1
Input–Outputbits 11–0 select one of 6 I/O operations (INP, OUT, SKI…) in exactly the same one-bit-per-op style

And when D7 = 0, the instruction is memory-reference, and that same bit 15 keeps its original meaning: I = 1 now means indirect addressing (§5.5), not "this is an I/O instruction." The control unit never has to explicitly check which meaning applies — D7 already encodes it, so every control equation downstream is written as D7′·I·(…) for indirect, or D7·I·(…) for I/O, and the two can never fire together.

The control equation this producesD7′ · I · T3:  AR ← M[AR] — "if this is a memory-reference instruction (D7′), and it's marked indirect (I), and we're at T3, then fetch the effective address." This single line is the entire indirect cycle from a control-unit's point of view.

5.5Indirect Addressing

A memory-reference instruction's 12-bit address field can point two different ways:

  • Direct addressing (I = 0) — the address field is the operand's location. AR already holds it after decode; execution can start immediately.
  • Indirect addressing (I = 1) — the address field points to a memory word that itself contains the operand's real address. One extra memory read is required before execution can begin, to follow that pointer.

Three shapes recur across all seven, and recognizing them is more useful than memorizing each line individually:

  • Read-modify-AC (AND, ADD, LDA) — read the operand into DR, then combine it into AC through the ALU.
  • Write-back (STA, and the store step of ISZ) — push a register's value out to M[AR] instead of reading from it.
  • Control transfer (BUN, BSA) — load PC directly, with BSA additionally using AR as scratch to save a return address before overwriting it with the jump target.
BSA, unpackedBSA ("Branch and Save Address") is a call instruction avant la lettre: it writes the current PC (the return address) into the memory word right before the subroutine, increments AR to point at the subroutine's first instruction, then jumps there. The subroutine returns later with an indirect BUN through that same saved word.

5.7Register-Reference Instructions

Register-reference instructions are structurally simpler than memory-reference ones in one specific way: there is no address field, no AR involvement, and therefore no execute phase that spans multiple T-states — every one of them completes in the single cycle right after decode.

The shared conditionEvery register-reference operation is gated by the same three-way AND: D7′· I· T3 — wait, that's indirect's condition. Register-reference instead uses D7· I′· T3: D7 says "not memory-reference," I′ says "not I/O," T3 says "we just finished decoding." One specific bit among IR(11–0) then selects which operation actually fires.

Because that whole condition collapses to a single T-state, twelve different micro-operations can share the same timing signal and simply differ in which bit of IR gates them:

Instr.Control functionMicro-operation

CLED7 I′ T3 B10E ← 0
CMAD7 I′ T3 B9AC ← AC′
CMED7 I′ T3 B8E ← E′

This is exactly the register-reference field from §5.1's instruction-format figure, now connected to hardware: each of the 12 bits in bits 11–0 is wired to its own AND gate alongside D7 I′ T3, and that gate's output is the actual control line reaching the register it affects.

5.8Input–Output Instructions

I/O instructions mirror register-reference instructions almost exactly — same "one bit selects one operation" pattern, same single-cycle execution — with the condition flipped to D7· I· T3 (I/O, not register-reference) and the targets being INPR/OUTR and the flag bits FGI/FGO instead of AC.

Instr.Micro-operation
INPAC(0–7) ← INPR, FGI ← 0
OUTOUTR ← AC(0–7), FGO ← 0
SKIskip next instruction if FGI = 1 (input device is ready)
SKOskip next instruction if FGO = 1 (output device is ready)
ION / IOFIEN ← 1 / IEN ← 0  (interrupt enable, §5.9)

FGI and FGO are the crux of the whole I/O scheme: an input device sets FGI = 1 whenever it has a byte ready, and clears it once INP has consumed that byte. A program can either poll this flag directly with SKI, or — as the next section covers — let the CPU notice it automatically via interrupts.

5.9The Interrupt Cycle

Polling a flag with SKI works, but it wastes cycles checking a device that usually isn't ready. Interrupts flip the arrangement: the CPU itself checks, automatically, at one fixed point in every instruction cycle — right after execution finishes, before the next fetch begins — rather than a program having to ask.

Two single-bit flip-flops make this possible:

  • IEN — Interrupt Enable, set/cleared by the program itself with ION/IOF. If IEN = 0, interrupts are simply ignored, no matter what the devices are doing.
  • R — the interrupt flip-flop. It's normally 0; the check IEN·(FGI + FGO) is performed once per instruction cycle, and if it's true, R is set to 1 right then.

R = 1 is what actually redirects the CPU: instead of a normal fetch, the next cycle runs the interrupt cycle instead — saving where execution was, and jumping to a fixed service-routine address.

The interrupt cycle itself (R = 1, in place of fetch) RT0: AR ← 0, TR ← PC
RT1: M[AR] ← TR, PC ← 0
RT2: PC ← PC + 1, IEN ← 0, R ← 0, SC ← 0

In words: the return address (the old PC) is saved into memory location 0, PC is redirected to location 1 — the fixed entry point of the interrupt service routine — and IEN is cleared so a second interrupt can't preempt the handler before it's ready. The handler ends with an indirect BUN 0 I, which reads the saved return address back out of location 0 and jumps there, resuming exactly where the program left off.

5.10The Complete Instruction Cycle

Every section above is one piece of a single repeating loop. Fetch and decode always run; indirect resolution and the interrupt cycle are conditional; execute always runs exactly once, in one of the three shapes covered in §§5.6–5.8. This is the shape the CPU is in forever, from power-on until it's halted:

Chapter 5 — key takeaways

  • The Basic Computer is eight registers, memory, a bus, an ALU, and a control unit — the control unit reads only IR and the T-state, and outputs only enable/select signals.
  • Bit 15 (I) and bits 14–12 (opcode/D7) together classify every instruction into memory-reference, register-reference, or I/O — three formats sharing one 16-bit word.
  • T-states are decoded from a free-running sequence counter, exactly like the bus-select decoder from Chapter 4 — there's nothing magic about T3.
  • Fetch and decode are identical for every instruction; indirect addressing inserts one optional extra memory read to resolve a pointer before execution.
  • Execution takes one of three shapes: the 7-way memory-reference fork, single-cycle register-reference operations, or single-cycle I/O operations.
  • The interrupt cycle is a CPU-driven check performed once per instruction cycle — an automatic alternative to polling FGI/FGO by hand.
  • All of it is one loop: Fetch → Decode → (Indirect) → Execute → Interrupt check → Fetch…

That loop is the entire Basic Computer. Every idea from Chapter 4 — RTL notation, the common bus, the ALU — exists only to make one iteration of it possible; every section of Chapter 5 exists only to decide which of that loop's branches gets taken next. Step through it instruction by instruction in the simulator to see the same T-states, decode logic, and control signals from this page acting on real memory and registers.
